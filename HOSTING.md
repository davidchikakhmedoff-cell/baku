# Перенос на хостинг MTA

Используйте актуальный MTA:SA 1.6 для Linux и клиент 1.6. Ресурсы рассчитаны на
SQLite; MySQL, адрес локального компьютера и дополнительный SQL-сервер не нужны.

## Обновление существующего сервера

1. Остановите сервер штатно, чтобы он сохранил данные и закрыл SQLite.
2. Сделайте резервную копию всей папки `resources` и конфигурации сервера.
3. Обновите код `rp_core`, `rp_home`, `rp_car`, `rp_fraction`, `baku_map` и папку
   `[cars]`. Сохраняйте точный регистр имён файлов и названия ресурсов.
4. Не удаляйте и не заменяйте базы: `rp_core/auth.db`, `rp_core/systems/bans/bans.db`,
   `rp_home/homes.db`, `rp_car/rp_car.db`. Фракции используют таблицы внутри
   `rp_core/auth.db`, отдельной базы фракций нет. После штатной остановки переносите
   базы из реально использовавшихся папок ресурсов; новая пустая база не содержит
   прежних аккаунтов/машин. Папки должны быть доступны на запись пользователю MTA.
5. Запустите сервер с такими записями в `mtaserver.conf`:

```xml
<resource src="rp_core" startup="1" protected="0" />
<resource src="rp_home" startup="1" protected="0" />
<resource src="rp_car" startup="1" protected="0" />
<resource src="rp_fraction" startup="1" protected="0" />
<resource src="baku_map" startup="1" protected="0" />
```

Зависимости в `meta.xml` также обеспечивают порядок core → home → car → fraction
при отдельном `start rp_fraction`. Модели из `[cars]` запускаются как зависимости
`rp_car`. Не запускайте отдельно вложенный старый ресурс `rp_car/toner`:
актуальная тонировка уже подключена в `rp_car/meta.xml`.

После первого запуска выполните в консоли хостинга:

```text
aclrequest list rp_core
aclrequest allow rp_core all
```

В текущем `rp_core/meta.xml` запрошены ровно два права: `function.kickPlayer`
(кик и отключение забаненного игрока) и `function.loadstring` (перечитывание
локального конфига администраторов через `reloadadmins`). MTA требует подтверждать
такие права в консоли сервера. Не требуется добавлять ресурсы в группу Admin.
Фракционные команды вызывают собственные обработчики с серверными проверками
ранга/смены; выдача расширенных ACL-прав не нужна.

Стандартные `play` и `freeroam`, если они включены в конфигурации хостинга,
могут вмешиваться в спавн и управление транспортом. Проверьте их обработчики;
для этого RP-сервера они не являются зависимостями.

## Проверки

Перед загрузкой: `python3 tools/check_resources.py` проверяет все `meta.xml`,
зависимости и регистр путей к файлам. Проверка не меняет игровые данные.

После загрузки в консоли сервера выполните `rphealth`. Команда выведет состояния
ресурсов и моделей, загруженные экспорты, файлы самого rp_core, ACL-права
и доступность базы аккаунтов. Файлы всех ресурсов проверяйте утилитой перед
загрузкой: стандартный ACL запрещает одному ресурсу читать файлы другого.
В игре `/rphealth` доступна администратору с правом `adminCommands`.

Проверьте в игровом клиенте: вход, HUD, TAB, команды и рации, вступление/смену,
выдачу и возврат ключей, N/двигатель/ручник, топливо, покупку/сохранение машины,
дома/отели, лечение, наручники, розыск и КПЗ. Повторите выдачу ключей сразу после
начала смены и с задержкой сети. Данные должны сохраниться после повторного входа
и штатного перезапуска сервера. Для проверки нужен клиент; консольный запуск
не подтверждает работу интерфейсов и заменённых моделей.

Если что-то не работает, пришлите вывод `rphealth` и соответствующий участок
`mods/deathmatch/logs/server.log`, а для моделей/интерфейсов — ошибки клиента.
